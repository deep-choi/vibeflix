# VIBEFLIX

한국어 바이브 코딩 서비스 쇼케이스. 전체 화면 추천 배너, 가로 작품 목록, 검색·카테고리·정렬·찜하기와 실제 서비스 바로가기를 제공합니다.

## 현재 서비스

기본 작품은 D1 `projects` 테이블(`source='catalog'`)에 있고 운영자 대시보드에서 관리합니다. `public/catalog.json`은 처음 데이터를 넣을 때(마이그레이션 `0006`)와 API 장애 시 대체 목록, ‘기본 디자인으로’ 되돌릴 때만 씁니다. Koiworld, Dayflow, 네모낚시, LearnHub, Deepchoi의 실제 공개 URL을 연결했고 GOD OF TOP, VOYAGE는 공개 준비 중으로 표시합니다. 카드에는 기존 프로젝트의 스토어 이미지·화면과 소스 설명을 사용합니다. VOYAGE 풍경은 콘셉트 이미지입니다.

## 실행

Node.js 22.13 이상. `npm run install:ci`로 의존성을 설치하고 `npm run dev`로 실행합니다. Windows npm shim 문제가 발생하면 `node scripts/run-framework.mjs dev`를 사용할 수 있습니다.

프런트엔드: `app/site.html`, `public/style.css`, `public/app.js`.
서버: Vinext API routes, Cloudflare D1 (`DB`). Sites starter의 호스팅 통합을 유지합니다.

## 디자인 시스템

버튼·입력칸·칩·배지·탭·알림·토스트·모달의 생김새와 동작은 `public/ds.css`·`public/ds.js` 한 곳에서 정해요. 모든 페이지가 가장 먼저 불러오고, 페이지 CSS는 `@layer page` 안에서 배치만 맡아요(시스템이 항상 우선). 휴대폰(≤640px)에서 모달은 아래에서 올라오는 시트가 되고, 글을 쓰는 모달은 닫기 전에 물어봐요. 규칙과 예전 클래스 대응표는 `docs/DESIGN_SYSTEM.md`, 모든 컴포넌트 견본은 `/design-system`에 있어요.

## 로그인과 커뮤니티

- VIBEFLIX 회원가입·로그인(이메일·비밀번호): Firebase Authentication 이메일 로그인을 씁니다. 가입하면 인증 메일이 가고, 이메일 인증을 마쳐야 로그인(세션 발급)됩니다. 비밀번호 재설정 메일도 Firebase가 보냅니다(메일 언어: 한국어). 비밀번호는 우리 DB에 저장하지 않습니다. 같은 이메일의 Google·이메일 로그인은 Firebase에서 같은 계정이면 같은 프로필을 씁니다. 회원의 마지막 로그인 방식은 `profiles.login_provider`에 남고 운영자 회원 목록에 보입니다.

- ChatGPT 로그인과 VIBEFLIX 전용 Firebase Google 로그인.
- Google ID 토큰의 서명·프로젝트·제공업체·만료·최근 인증·계정 상태를 서버에서 확인합니다. 로그인 세션은 서버 D1에 해시로 저장하고 브라우저에는 HttpOnly 쿠키를 사용합니다.
- 카테고리별 게시판(작품 소개·개발 일지·질문·피드백·자유 이야기), 검색, 최신순/추천순, 더 보기, 글 작성·수정·목록에서 내리기, 로컬 초안 자동 저장.
- 작품과 게시글의 댓글·대댓글, 댓글 수정·삭제, 댓글 추천과 답장 알림.
- 작품별 1~5점 별점과 한 줄 리뷰. 계정당 한 개 평가를 저장하고 재평가하면 수정합니다. 평균·평가 수를 보여줍니다.
- 작품·글·댓글의 추천은 계정당 한 번 집계하고 취소할 수 있습니다. 별점 높은 순과 이용자 추천순 정렬을 제공합니다.
- 로그인한 계정의 찜 목록 동기화. 비로그인 찜은 로컬 저장입니다.
- 프로필 닉네임·소개 수정, 내 작품·글·댓글 목록, 공개 작품 수정·내리기·다시 공개.
- 신고 접수·중복 방지·원문 검토와 운영자 숨김 처리. 운영자가 숨긴 작품은 작성자가 임의로 복구할 수 없습니다.
- 서비스·게시글 공유 링크와 댓글/목록 페이지 단위 불러오기.

Google 공개 설정은 `public/firebase-config.json`에 있습니다. Firebase 프로젝트는 `vibeflix-community-choi`이며 다른 기존 서비스의 Firebase와 분리했습니다. 공개 Firebase API 키는 인증 토큰이나 서비스 계정 비밀키가 아닙니다. Google와 ChatGPT 계정은 자동 병합하지 않습니다.

운영자 이메일은 배포 런타임의 비밀 환경 변수 `ADMIN_EMAILS`로 설정합니다. 첫 방문자에게 자동 운영자 권한을 부여하지 않습니다. 운영자는 로그인 후 내 프로필의 ‘신고 관리’에서 접수된 신고를 검토합니다.

## 공용 등록

- 방문과 서비스 이용 링크는 비로그인 상태로 접근할 수 있습니다.
- 작품 등록은 Google 또는 ChatGPT 로그인으로 인증합니다.
- 공개 작품 정보는 D1에 저장되어 모든 방문자에게 보입니다. 계정 ID는 반환하지 않습니다.
- 작성자는 자신의 커뮤니티 작품만 목록에서 내릴 수 있습니다. 데이터는 soft delete로 보존됩니다.
- 요청 출처, 필수 입력, 공개 http(s) URL, 중복 링크와 하루 10건 등록 제한을 서버에서 확인합니다.
- 로그인한 찜 목록은 D1, 비로그인 찜 목록은 현재 브라우저의 localStorage에 저장됩니다.
- 사용자 입력 링크의 보안·콘텐츠를 자동 심사하지는 않습니다.

## 데이터베이스와 검증

스키마는 `db/schema.ts`, 마이그레이션은 `drizzle/`입니다. 스키마 수정 후 `npm run db:generate`로 새 마이그레이션을 만듭니다. 로컬 D1은 빌드 후 Sites starter README의 방식으로 마이그레이션을 적용해야 합니다. 호스팅 D1에는 Sites 배포 시 적용됩니다.

`node scripts/check-api.mjs http://127.0.0.1:5174`는 ChatGPT Sites 미리보기(모의 ChatGPT 로그인이 있는 환경)에서만 실행할 수 있으며 임시 레코드를 만들고 내립니다. 공개 조회, 인증, 출처 검사, 잘못된 URL, 공용 저장, 중복, 작성자 소유권과 soft delete를 검증합니다. `npm start`(Workers 로컬)에는 모의 로그인이 없어 첫 단계에서 멈춥니다.

`node scripts/check-community.mjs http://127.0.0.1:5297`는 두 명의 로컬 테스트 사용자를 만들어 인증·권한·게시글·댓글·답글·알림·추천 중복 방지·별점·찜·신고·운영자 숨김·복원 제한·위조 로그인 거부·로그아웃을 검증하고 임시 데이터를 정리합니다. 프로덕션 URL에서는 실행되지 않습니다. 기본 미리보기 포트가 다른 프로젝트와 겹치면 `node scripts/run-framework.mjs dev --port 5297`로 시작하세요.

로컬에서 Workers와 같은 환경으로 확인하는 순서:

```
npm run build
npm run db:migrate:local          # drizzle/*.sql을 .wrangler/state의 로컬 D1에 순서대로 한 번씩 적용
npm start -- --port 5297
node scripts/check-operator.mjs http://127.0.0.1:5297   # 운영·작가 도구 (0015)
node scripts/check-personas.mjs http://127.0.0.1:5297   # 페르소나 개선 (0016)
node scripts/check-community.mjs http://127.0.0.1:5297
node scripts/check-security.mjs http://127.0.0.1:5297    # 보안 헤더·로그인 위조·캐시·조회수 (0017)
```

네 스크립트 모두 로컬 주소에서만 돌고, 만든 임시 회원·작품·글을 끝에 지웁니다. 로컬 wrangler가 가끔 앱까지 가지 않은 503을 즉시 돌려주는데(앱의 503은 항상 JSON 오류와 함께 `daily_errors`에 기록됨), 이런 응답만 두 번까지 다시 시도합니다.

GitHub Actions `CI`(`.github/workflows/ci.yml`)가 push·PR마다 lint, 타입 검사, 빌드, 로컬 D1 마이그레이션, 위 네 스크립트를 실행합니다. Cloudflare 계정이나 비밀값은 필요 없습니다.

새 마이그레이션 `0001`, `0002`는 추가 테이블과 nullable 열만 생성합니다. 기존 작품 레코드는 유지합니다. 테스트 fixture와 OAuth 토큰, Firebase CLI 로그, 실행 상태는 배포 소스에 포함하지 않습니다.

## 보안과 성능 (마이그레이션 0017)

- **ChatGPT 로그인 헤더**: `oai-authenticated-user-*` 헤더는 ChatGPT Sites 플랫폼이 붙여주는 값이라, Sites 주소(`*.chatgpt.site`)로 들어온 요청에서만 믿습니다(`app/chatgpt-auth.ts`). Workers에서는 누구나 이 헤더를 직접 보낼 수 있어서 예전에는 아무 이메일(운영자 이메일 포함)로 로그인한 것처럼 꾸밀 수 있었습니다. 다른 주소에서 Sites 앞단을 쓴다면 비밀이 아닌 변수 `CHATGPT_SITES_AUTH=1`로 직접 켜야 합니다.
- **보안 헤더** (`lib/security.ts`, 정적 파일은 `public/_headers`): `nosniff`, HSTS, Referrer-Policy, Permissions-Policy, Google 로그인 팝업을 막지 않는 COOP, 그리고 `object-src 'none'; base-uri 'self'; form-action 'self'` CSP. `/admin`은 다른 사이트 안에 넣을 수 없습니다(`frame-ancestors 'none'`). 다음 단계는 인라인 스크립트·스타일을 파일로 옮긴 뒤 `script-src`/`style-src` 허용 목록을 거는 것입니다(Firebase·gstatic·YouTube·Vimeo·itch.io 포함).
- **조회 수**: 작품 조회·링크 클릭·회차 조회는 같은 방문자(그날의 IP+브라우저 해시)에게서 하루 한 번만 셉니다(`view_dedupe`, 이틀 뒤 삭제). 작가 본인이 자기 작품을 열어도 세지 않고, 숫자를 올리려는 반복 요청은 무시됩니다. 집계는 `waitUntil`로 응답 뒤에 처리해 페이지를 늦추지 않습니다.
- **캐시**: 페이지가 링크하는 `/ds.css`·`/app.js` 같은 파일에는 빌드마다 바뀌는 `?v=`가 붙고(vite `define` → `__ASSET_VERSION__`), 브라우저는 1년 동안 다시 받지 않습니다. `public/`에 CSS·JS를 추가하면 `public/_headers`에도 한 줄 넣으세요(`check-security`가 빠진 것을 잡습니다). 사이트맵은 Worker마다 10분 보관하고, 같은 Worker에서 작품이 바뀌면 바로 새로 만듭니다.
- **인덱스**: 찜(작품별), 신고(대상별), 운영 기록(대상별), 작품 통계(날짜별), 게시글(분류별) 조회에 인덱스를 더했습니다. 읽은 지 90일 지난 알림은 가끔 정리됩니다.
- **의존성**: `next` 16.4.5(ImageResponse 원격 코드 실행·Draft Mode 노출 수정), React 19.2.8(Server Functions DoS), sharp 0.35.5, zod 4, 그 밖의 간접 의존성을 패치했습니다. `npm audit --omit=dev`는 0건입니다. 남은 경고는 개발 도구(wrangler의 esbuild 개발 서버, eslint의 minimatch, vinext의 image-size·satori)뿐이라 운영 Worker에는 들어가지 않으며, vinext 1.x 정식 버전으로 올릴 때 함께 정리합니다.

## Cloudflare Workers 배포 (운영 사이트)

운영 주소는 **https://vibeflix.cryingonion77.workers.dev** 입니다. Worker 이름은 `vibeflix`, D1 데이터베이스는 `vibeflix-db`입니다. Cloudflare 계정에 로그인(`wrangler login`)한 상태에서:

```
npm run deploy:workers            # 빌드 → 새 마이그레이션 적용 → 배포
npm run deploy:workers -- --dry   # 실행할 명령만 확인
```

`scripts/deploy-workers.mjs`가 `dist/server/wrangler.json`의 Worker 이름·D1 연결을 실제 값으로 바꾸고 Workers 로그(observability)를 켭니다. 적용한 마이그레이션은 원격 D1의 `_vibeflix_migrations` 테이블에 기록해 다시 실행하지 않습니다. 스키마를 바꿨다면 먼저 `npm run db:generate`로 마이그레이션을 만듭니다.

- 운영자 권한: `npx wrangler secret put ADMIN_EMAILS --name vibeflix` (쉼표로 여러 개). 설정 후 그 이메일로 **다시 로그인**하면 운영자가 됩니다.
- ChatGPT 로그인은 Sites 전용이라 Workers에서는 버튼이 자동으로 숨겨집니다. Google 로그인은 Firebase 승인 도메인에 `vibeflix.cryingonion77.workers.dev`가 등록되어 있습니다.
- 로그: Cloudflare 대시보드 → Workers → vibeflix → Logs, 또는 `npx wrangler tail vibeflix`.
- 백업·복구: D1은 최근 30일 안의 시점으로 되돌릴 수 있습니다. `npx wrangler d1 time-travel info vibeflix-db`로 확인하고 `npx wrangler d1 time-travel restore vibeflix-db --timestamp=<ISO 시각>`으로 복구합니다. 따로 보관하려면 `npx wrangler d1 export vibeflix-db --remote --output backup.sql`.
- 정기 백업: `.github/workflows/backup.yml`이 매일 03:17(KST)에 원격 D1을 내보내 30일 보관하는 아티팩트로 올립니다. 저장소 비밀값 `CLOUDFLARE_API_TOKEN`(D1 읽기 권한)과 `CLOUDFLARE_ACCOUNT_ID`를 넣어야 동작하고, 없으면 건너뜁니다. 내보낸 파일에는 회원 정보가 들어 있으니 저장소를 비공개로 두세요.
- 오류 알림: 운영자 대시보드 ‘현황’에 날짜별 서버 오류 수가 보입니다. 바로 알림을 받으려면 Cloudflare 대시보드 → Notifications에서 Workers 오류율 알림을 켜세요.
- 약관·방침 변경: 0015·0016과 함께 이용약관(운영 조치, 권리 침해 신고)과 개인정보처리방침(통계·제재 기록)이 바뀌었습니다. 이용약관 제9조에 따라 시행 7일 전에 공지 띠로 알리고, `lib/legal.ts`의 시행일을 실제 날짜로 맞추세요. 동의를 다시 받지는 않도록 `POLICY_VERSION`은 그대로 두었습니다.

## 작품 상세 페이지와 에디터

모든 작품은 `/works/:id` 상세 페이지를 가집니다. 영상은 맨 위에 YouTube·Vimeo 플레이어가 나오고, 나머지는 커버 → 제목·카테고리 정보 → 소개 → 본문 순서로 세로로 이어서 봅니다. 카드를 누르면 지금처럼 미리보기 창이 뜨고, 창의 ‘상세 페이지’나 페이지의 ‘별점 · 댓글’(`/#work=ID`)로 오갈 수 있습니다.

- 본문(`projects.content`): 소제목·글·이미지 블록을 순서대로 쌓습니다. 블록 60개, 이미지 8장(장당 700KB, 자동 최적화), 글 50,000자까지. 이미지는 `project_images`에 저장됩니다.
- 카테고리 전용 항목(`projects.details`): 웹사이트 주요 기능·사용 기술 / 앱 플랫폼·App Store·Google Play / 게임 플레이 방식·시간·조작법·트레일러 / 그림·만화 형식(웹툰·만화는 이미지가 간격 없이 이어짐) / 영상 길이 / 소설 연재 상태.
- 링크 규칙: 웹사이트·게임은 링크 필수, 앱은 웹 링크나 스토어 링크 중 하나, 영상은 YouTube·Vimeo 링크 필수, 그림·만화·소설은 선택.
- 예시 작품도 같은 페이지를 씁니다(`/samples/:id`는 `/works/:id`로 이동). 예시 본문은 `lib/sample-content.ts`에 있습니다.

## 회차 · 소식, 팔로우, 작가 통계

- 회차·소식(`entries`): 소설·그림·영상은 회차(1화, 2화…), 앱·게임·웹사이트는 업데이트 노트(버전)입니다. 작품 페이지에서 작가가 직접 쓰고(블록 에디터 공용 `public/block-editor.js`), 임시 저장·예약 공개·작가의 말을 지원합니다. 회차 페이지는 `/works/:id/e/:entryId`(이전·다음 화, 이어 보기).
- 알림: 회차·소식이 공개되면 그 작품을 찜한 사람과 작가 팔로워에게 한 번씩 알립니다. 예약 공개는 공개 시각 이후 첫 조회 때 알립니다.
- 크리에이터 페이지 `/creators/:id`: 프로필, 공개 작품, 최근 회차·소식, 팔로우.
- 작가 통계(`work_stats`): 작품 페이지·미리보기 조회와 외부 링크 클릭을 하루 단위로 셉니다. 작가 본인에게 작품 페이지 위쪽 ‘내 작품 관리’로 보입니다.
- 작품 임시 저장(`projects.visibility='draft'`): 작가만 보고, 공개하면 목록에 나옵니다.
- 상세 페이지 안에서 별점·리뷰·댓글·찜·추천·공유를 할 수 있고, 앱·게임·웹사이트 댓글은 ‘피드백’·‘버그 제보’로 분류할 수 있습니다.
- 공통 ‘AI로 만든 과정’(사용한 AI 도구, 제작 기간, 과정, GitHub·오픈소스)과 카테고리 항목(연재·단편, 소재 경고, 앱 가격·베타, 게임 개발 단계·조작 장치·itch.io 플레이, 영상 챕터·크레딧, 그림 라이선스)을 받습니다. 커버는 아무 이미지나 16:9로 자동으로 맞춥니다.

## 운영자 대시보드

운영자 계정으로 로그인하면 헤더에 ‘운영’ 버튼이 보이고 `/admin`으로 들어갑니다. 모든 작업은 `/api/admin`을 거치며 운영자 세션이 필요합니다.

- 현황: 회원·작품·글·댓글 수, 오늘 늘어난 수, 처리 대기 신고, 최근 14일 방문자. 방문자는 IP를 저장하지 않고 하루 단위 해시로만 셉니다(90일 뒤 삭제). 그 아래에 이의 제기·탈퇴 요청 대기, 7일간 서버 오류 수, 가입 흐름(방문 → 가입 → 첫 활동 → 첫 작품), 이번 주 많이 본 작품, 결과가 없던 검색어(계정과 연결하지 않고 90일 보관), 카테고리별 작품 수 대비 조회(작가 모집이 필요한 곳 표시).
- 작품: 수정(이름·크리에이터·카테고리·공개/공개 예정·링크·한 줄 소개·소개·태그), 썸네일 교체(아무 이미지나 고르면 16:9로 잘라 1280×720으로 맞춤), 기본 작품은 ‘기본 디자인으로’ 되돌리기, 숨기기/다시 공개(작성자에게 사유와 이의 제기 방법이 알림으로 감), 영구 삭제(이름 입력 확인, 댓글·추천·별점·찜·신고 함께 삭제), ‘지금, 주목할 바이브’ 맨 앞 고정과 순서 변경(최대 10개), 회원 작품의 ‘링크 확인’ 표시(확인 전 링크는 방문자에게 이동 경고가 뜨고, 작성자가 링크를 바꾸면 확인이 풀림). ‘공개 예정’ → ‘공개’로 바꾸면 찜한 사람에게 공개 알림이 갑니다. 100개씩 더 보기.
- 배너: 홈 상단 슬라이드 추가·수정·삭제·켜기/끄기·순서 변경(최대 10개), 시작·끝 시각 예약. 연결 작품, 제목, 설명(세 줄), 버튼 문구·아이콘·링크, 디자인(코이월드·네모낚시·Dayflow 테마 또는 올린 이미지를 배경 전체에 쓰는 ‘직접 꾸미기’)을 고릅니다.
- 기획전: 홈 ‘지금, 주목할 바이브’ 아래에 한 줄씩 나오는 작품 묶음(최대 20개, 묶음당 30작품). 제목·한 줄 설명·작품 순서·시작/끝 시각·켜기/끄기.
- 회원: 제재(경고 → 7일 정지 → 30일 정지 → 영구 정지, 사유는 회원에게 알림으로 전달, 기간 정지는 시간이 지나면 다음 접속 때 저절로 풀림)와 기록 보기, 정지 해제, 운영자 지정/해제, 영구 삭제(작품·글·댓글·추천·별점·찜·알림·제재 기록까지 삭제). 내 계정과 운영자는 제재·삭제할 수 없습니다.
- 탈퇴 요청: 오래된 순서로, 기다린 날수와 함께(5일 이상이면 강조). 삭제 처리 또는 요청 취소.
- 게시글·댓글: 검색, 숨김만 보기, 숨기기/다시 공개, 영구 삭제(답글 포함).
- 신고: 같은 대상에 들어온 신고를 한 줄로 묶어 신고 수가 많은 순으로 보여줍니다. 신고 분류(스팸·광고, 욕설·괴롭힘, 도용·저작권, 개인정보 노출, 음란·선정성, 악성 링크·사기, 기타)와 가입 7일 이내 신고자 수(집단 신고 판단용)를 함께 보여줍니다. 처리하면 신고자 모두에게 결과가, 작성자에게 숨긴 사유가 알림으로 갑니다. 회원 신고는 경고·정지로 처리합니다. 대상마다 첫 신고가 들어오면 운영자에게 알림이 한 번 갑니다. 신고 수만으로 자동 숨김은 하지 않습니다(집단 신고 악용 방지).
- 이의 제기: 숨겨진 작품·글·댓글의 작성자가 보낸 재검토 요청. 받아들이면 바로 다시 공개, 기각하면 사유를 작성자에게 전달.
- 사이트 설정: 상단 공지 띠(문구·링크·자동으로 내릴 시각), 개인정보처리방침·이용약관에 공개할 문의 이메일, 예시 콘텐츠 모두 지우기.
- 예시 콘텐츠(마이그레이션 `0008`): 빈 카테고리를 채우는 임시 작품 12개(그림·만화·영상·소설, 표지는 `public/assets/samples/`), 게시판마다 글 2개, 카테고리 배너 3개. `source='sample'` / 작성자 `system:sample`이며 사이트에 ‘예시’로 표시되고 링크가 없습니다. 홈 배너와 ‘지금, 주목할 바이브’에는 나오지 않습니다.
- 처리 기록: 모든 운영 작업을 사유와 함께 남기고, 대상 종류별 필터·검색·더 보기를 제공합니다.

## 페르소나 기반 개선 (마이그레이션 0015 · 0016)

방문자, 작가, 커뮤니티 참여자, 운영자 유형별로 실제 사용 흐름을 따라가며 보강한 기능입니다. 두 마이그레이션 모두 테이블·열 추가만 하며 기존 데이터를 바꾸지 않습니다.

- 처음 온 사람: 홈 배너 아래 한 문단 안내와 ‘바로 플레이하는 게임 / 쓸 만한 도구 / 읽을거리’ 버튼(한 번 닫으면 다시 안 보임).
- 게임·앱 이용자: 미리보기에 설치 정보(플랫폼·가격·App Store/Google Play), 사용 기술, 만든 AI 도구, 함께 만든 사람. 웹 링크 없이 스토어만 있는 앱은 스토어 버튼이 기본 버튼. 외부 링크를 열고 20초 넘게 있다가 돌아오면 별점 남기기를 권합니다. 별점 분포를 보여줍니다.
- 독자·시청자: 홈 ‘이어서 볼 작품’ 줄(이 기기에만 저장, 마지막에 본 회차로 바로 이동), 팔로우한 작가의 새 회차·새 작품 줄, 회차별 댓글, 마지막 회차 끝의 ‘찜하고 알림 받기’, 연재 요일 안내, 영상 챕터(누르면 그 장면부터 재생). 공개 예정 작품은 ‘출시 알림 받기’.
- 작가: 작품을 ‘개발 중’으로 링크 없이 먼저 올리고 공개로 바꾸면 찜한 사람에게 알림, 소개 틀 넣기, 첫 작품을 올리면 피드백 요청 글을 미리 채워 제안, 선택 항목은 ‘더 자세히 소개하기’로 접힘(비개발자 카테고리는 GitHub 항목 없음), 앱·게임 사용 기술, 함께 만든 사람, 연재 요일. 작품 페이지 ‘내 작품 관리’에 30일 조회 그래프, 유입 경로(이전 사이트 주소 이름만), 회차별 조회와 1화 대비 남은 독자 비율. 피드백·버그 제보 댓글을 ‘확인함 / 반영됨(업데이트 소식 연결)’으로 표시하면 남긴 사람에게 알림. 프로필 링크(최대 3개)와 작품별 기술 스택이 크리에이터 페이지에 보여 포트폴리오로 쓸 수 있습니다.
- 커뮤니티: 질문 글에서 답변 채택(‘해결됨’, 답한 사람에게 알림), ‘답변 기다리는 질문만’ 필터, ‘대화 활발한 순’ 정렬.
- 안전: 내 작품·글 추천과 내 작품 별점 금지, 같은 댓글 반복 금지(짧은 인사는 다른 글에는 허용), 가입 첫날 작품 2개·링크 댓글 시간당 3개 제한, 성인 소재 경고 작품은 목록에서 흐리게 보이고 작품·회차 페이지에서 확인 후 열림, 저작권 신고는 원본 링크를 요구, 이용약관에 권리 침해 신고(게시 중단) 절차 추가. 임시 저장 작품과 공개 전 회차의 이미지는 작성자만 볼 수 있고 공개 캐시에 남지 않습니다.
- 성능: 작품 목록은 200개씩 나눠 받아 개수 제한 없이 모두 보이고, 로그인하지 않은 방문자의 목록 응답은 Worker 인스턴스마다 30초 동안 메모리에 보관합니다(쓰기가 일어난 인스턴스는 즉시 비움). workers.dev에서는 Cache API를 쓸 수 없어 메모리 방식입니다.
- 검색 노출: `/sitemap.xml`(공개 작품·크리에이터·회차, 예시 제외)과 `/robots.txt`.

아직 하지 않은 것: 이미지 저장소를 D1에서 R2로 옮기기(버킷 생성과 기존 데이터 이전이 필요), 푸시·이메일 알림(발송 서비스와 키가 필요), 뉴스레터용 이메일 수집(수신 동의와 개인정보처리방침 변경이 필요).
